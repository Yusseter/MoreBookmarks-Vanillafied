# Current Definition Override-Aware Province Tracking

## Summary

- `map_data/definition.csv` canlı hedef kabul edilecek; sistem artık `14630-14640` gibi hardcoded ID aralığı kullanmayacak.
- Current definition ile generated baseline karşılaştırılıp tüm farklar sınıflandırılacak: placeholder terfileri, mevcut candidate RGB/name değişiklikleri, yeni/eksik satırlar.
- Çözüm `Generator override (Recommended)` olarak kurulacak: generated CSV’ler elle patchlenmeyecek, `build_id_policy_drafts.ps1` override girdisini okuyarak doğru assignment/placeholder çıktısı üretecek.

## Key Changes

- Yeni helper script eklenecek: `works/tools/build_current_definition_overrides.ps1`.
- Bu script şu girdileri okuyacak: current `map_data/definition.csv`, baseline `works/analysis/generated/definition_birlesim_final_preserve_old.csv`, master `final_master_preserve_old_ids.csv`, source definitions `works/map_data_sources/definition_modlu.csv` ve `definition_orijinal.csv`.
- Çıktılar: `current_definition_diff_audit.csv`, `current_definition_override_candidates.csv`, `current_definition_override_summary.md`.
- Manual locator kaynağı ayrı CSV olacak: `works/manual/manual_locator_provinces.csv`.
- İlk manual locator CSV, mevcut marker’dan türeyen `14630-14634` ID’leriyle seed edilecek; bundan sonra authoritative kaynak CSV olacak, marker sadece audit bilgisi sayılacak.

## Implementation

- Placeholder terfisi kuralı: baseline/master’da `row_type = placeholder`, current definition’da RGB/name farklıysa bu ID gerçek row’a terfi etmiş sayılır.
- Existing candidate değişikliği kuralı: master’da `row_type = candidate`, current definition’da RGB/name farklıysa aynı source identity korunur, sadece `effective_rgb/effective_name` override edilir.
- Source identity çözümü exact RGB match ile yapılacak; source modda bulunursa `source_origin=modlu`, `preferred_source_subset=modlu_kalan`; source vanilla/orijinalde bulunursa `source_origin=orijinal`, `preferred_source_subset=orijinal_dogu`.
- Name match karar vermek için kullanılmayacak; sadece audit/report hint olacak. Exact RGB ambiguous veya missing ise satır assignment’a eklenmeyecek, blocker report’a düşecek.
- `build_id_policy_drafts.ps1` yeni `-DefinitionOverrideCandidatesCsv` parametresi alacak. Preserve policy üretirken override final IDs rezervlenecek, aynı ID’ler placeholder listesinden çıkarılacak, candidate değişiklikleri mevcut assignment row üstüne uygulanacak.
- `build_policy_master_tracking.ps1` büyük ihtimalle yapısal değişiklik istemeyecek; override assignment satırları mevcut kolon formatında üretilecek.
- `implement_core_province_integration.ps1` locator tarafında düzeltilecek: `modlu_kalan` için `modlu_old_id != final_new_id` olduğunda source locator eski ID’den alınacak ve final ID’ye rewrite edilecek.
- Manual locator ID’leri için locator auto-copy yapılmayacak. Script mevcut target locator dosyasında aynı final ID block’u varsa koruyacak; yoksa `missing_manual_locator` raporlayacak.

## Test Plan

- Diff audit current durumu doğru görmeli: 86 changed candidate ve 47 promoted placeholder satırı raporlanmalı.
- Rebuild sonrası `final_master_preserve_old_ids.csv` içinde current promoted IDs artık `placeholder` değil `candidate` olmalı.
- `id_policy_preserve_old_placeholders.csv` içinde promoted final IDs kalmamalı.
- `14630-14634` manual locator olarak raporlanmalı; auto-generated locator source’dan alınmamalı.
- `14635-14640` gibi non-manual source-mod rows için locator source old ID’den alınarak final ID’ye rewrite edilmeli.
- Duplicate RGB, missing ID, unresolved source identity ve landed-title province reference kontrolleri blocker olarak raporlanmalı.

- Current `map_data/definition.csv` ve current `map_data/provinces.png` canlı gerçeklik kabul edilecek; plan bunları hardcoded aralıkla değil baseline diff ile yorumlayacak.

- Full renumber policy bu işin hedefi değil; override sistemi preserve-old pipeline için authoritative olacak.
