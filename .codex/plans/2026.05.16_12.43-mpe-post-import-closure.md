# MPE Add 1 Sonrası Tutarlılık Kontrol ve Onarım Planı

## Summary

MPE importunu artık tek dosya düzeltmesi gibi değil, dört katmanlı bir tutarlılık turu olarak ele alacağız: `landed_titles`, localization, title/province history ve `gfx/map/map_object_data`. Önce read-only audit raporları üretilecek, sonra yalnızca kararları net olan sınıflar uygulanacak. `test_files` kullanılmayacak.

## Key Changes

- Yeni read-only audit scripti hazırlanacak: `works/tools/audit_mpe_add_1_consistency.py`.
- Yeni uygulama scripti ayrı olacak: `works/tools/apply_mpe_add_1_consistency_fixes.py`.
- Kullanıcı kararları CSV olarak tutulacak; hardcode yerine tabloyla uygulanacak:
  - `mpe_history_donor_map.csv`
  - `mpe_barony_alias_locator_map.csv`
  - `mpe_title_structure_fix_map.csv`
- Localization için kaynakta bulunmayan key otomatik üretilmeyecek; sadece raporlanacak.
- Donor source kuralı:
  - Current Yusseter’de yorumlu/silinmiş olsa bile, Levi kaynakta varsa donor geçerlidir.
  - Özellikle `c_don_portage` donor olarak Levi `common/landed_titles`, Levi `history/titles`, Levi `history/provinces` üzerinden okunacak.

## Implementation Plan

- Localization audit:
  - Tüm MPE eklenen/taşınan `b_`, `c_`, `d_` ve kullanılan `cn_*` keyleri taranacak.
  - Kaynak sırası: current localization’da var mı, MPE’de var mı, Levi’de var mı.
  - Eksikler raporlanacak; otomatik key üretimi yapılmayacak.
  - Bilinen örnekler: `b_khunzakh`, `c_majar`, `cn_iryston`.

- History donor fix:
  - Kullanıcının donor listesi tabloya çevrilecek.
  - Yazım düzeltmeleri kilitli:
    - `c_digora` -> `c_digoria`
    - `c_tapanda` -> `c_tapanta`
  - County title history ve capital barony province history, verilen donor county’den alınacak.
  - Capital barony yoksa ilk `b_*` capital sayılacak.
  - Culture/religion yalnızca target county’nin capital barony province’inde olacak.

- Landed title structure fix:
  - `c_besinada`, `c_majar`, `c_alania` donor’u `c_don_portage` olacak; donor current değil Levi kaynak kabul edilecek.
  - `c_kerch/c_cherson/c_korchev` tarafı ayrı özel kural olacak:
    - Current MPE `c_cherson` yapısı `c_kerch` karşılığı olarak ele alınacak.
    - `b_gialta` yerine `b_yalta`, `b_symbolon` yerine `b_yamboli`, `b_phoros` yerine `b_mangup` kullanılacak.
    - Bu isim değişimleri `# Yusseter: ...` yorumuyla işaretlenecek.
  - `b_targin` tek kaldığı county’den `c_ossetia` altına taşınacak.
  - `c_lazia` altındaki baronyler `c_avaria` altına taşınacak.
  - `c_perekop`, `c_khortytsia` ve benzer eski Levi county’lerde renk MPE’den değil Levi’den korunacak; audit bunu current/Levi/MPE karşılaştırmasıyla doğrulayacak.

- Map object locator fix:
  - Crimea özel eşleşmeleri tabloya yazılacak.
  - Kabul edilen strateji: eski ID’ler kullanılacak, locator verisi MPE donor ID’den alınacak.
  - İlk bilinen mapping:
    - `13359 -> 9837` for `b_gialta -> b_yalta`
    - `13360 -> 9836` for `b_symbolon -> b_yamboli`
    - `13361 -> 9835` for `b_phoros -> b_mangup`
  - `gfx/map/map_object_data` altındaki 6 locator dosyasında donor block kopyalanacak, target `id` eski ID’ye çevrilecek, yorum rapora yazılacak.
  - `13359/13360/13361` title association sonrası title’sız land province riski ayrıca validator raporunda kontrol edilecek; gerekirse non-playable/ignored sınıfına alınacak.

## Test Plan

- Duplicate title key `0` yeni MPE kaynaklı olmalı.
- Duplicate province assignment `0`.
- MPE eklenen/taşınan her playable land province’in landed title association’ı olmalı.
- History audit:
  - Target county title history var.
  - Target capital barony province history var.
  - Non-capital target barony province’lerinde culture/religion yok.
- Localization audit:
  - Missing key listesi raporlanır; otomatik doldurulmaz.
- Locator audit:
  - Donor/target ID eşleşmeleri 6 map object data dosyasında tam uygulanır.
  - Eski ve yeni ID’lerde duplicate locator block oluşmaz.
- `test_files` hash’i değişmemeli.

## Assumptions

- `test_files` sistemi kullanıcı tekrar söyleyene kadar kullanılmayacak.
- `c_don_portage` current dosyada yorumlu olsa da Levi kaynakta aktif olduğu için geçerli donor’dur.
- `c_digoria` ve `c_tapanta` kullanıcıdaki `c_digora/c_tapanda` yazımlarının doğru karşılığıdır.
- Localization kaynakta yoksa otomatik üretim yapılmayacak, raporlanacak.
- Kullanıcı ileride ek `b_*` alias mappingleri verirse aynı `mpe_barony_alias_locator_map.csv` tablosuna eklenerek uygulanacak.
